# 抓取精度与去重 —— 一分钟版(2026-09-03)

正式设计在同目录的 `2026-09-03-scan-precision-dedup-design.md`;这份只讲人话。

## 要解决的两个问题

1. 队列里混进了明明不能投的岗:不给签证、只要 PhD、根本不是工程岗。
2. 同一个岗在美国好几个城市各发一条,队列里看到一堆重复。

## 现在系统是怎么做的

**扫描进来之后,先去重。** 公司名和职位名一样的岗放一组,让 Claude 看一眼:哪些其实是同一个坑。是同一个的,只留一条主行(优先留洛杉矶,其次旧金山、纽约),其余的归档并标"重复:主行 #几号"。主行卡片上会写"另有 N 个地点"。

**打分的时候,顺手判资格。** 匹配 LLM 除了打分,还要明确回答三件事:给不给签证、是不是只要 PhD、是不是工程岗。只有招聘正文**白纸黑字**写了"不 sponsor / 仅公民 / 必须在读 PhD",才判不合格;申请表里问"你需要签证吗"不算证据。不合格的直接归档,原因写清楚。

**没有正文的岗,让 Claude 自己去看。** 很多岗(Workday、Tesla 之类)扫描时抓不到正文。现在有一个"补正文"按钮:Claude 用专属浏览器逐页打开,把完整正文抄回来,当场判资格。登录墙、已下线、打不开的分别标记,不硬闯、不登录、不填表。扫描完会自动接着补,每天最多 10 轮(每轮 40 页),防止失控。

**真去投的时候,再兜一次底。** 执行器打开申请页发现不合格,直接归档,连同它的重复项一起,不再进"需人工"名单。投递数量的意思也改了:填好等你确认的才算一份,被拦下的不算,继续取下一个。

## 你会看到什么变化

- `/queue` 更干净;卡片上有"另有 N 个地点""无正文""登录墙"这类小标签;展开能看到其他地点和资格判断。
- `/apply` 多了"补正文"按钮,旁边显示还有多少岗没正文。
- 所有归档都能撤销,不删任何数据;置顶的岗系统永远不会自动归档。

## 上线要做的四步(需要你确认)

1. 合并、部署(数据库自动升级)。
2. 备份数据库,然后跑存量去重(约 45 次 Claude 调用,几分钟)。
3. 用新规则把队列里的岗重打一遍(约 40 分钟,后台跑)。
4. 在 `/apply` 点一次"补正文",之后每天自动接力。
